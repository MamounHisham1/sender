Phone ⇄ laptop sync,
straight into the clipboard.

Send text and images between your Android phone and laptop over Wi-Fi. Anything received lands directly in that device's clipboard — no clicks needed.

Install the server — Linux / macOS
curl -fsSL …/install.sh | bash
Downloads a prebuilt binary in seconds, starts it in the background, and enables start-on-boot. --no-service opts out. Source
📋

Clipboard-direct

Received text and images go straight into the OS clipboard on both sides. Laptop images are also saved under ~/Pictures/Sender/.

📷

QR pairing

The server shows a QR code. Scan it from the app once — host and PIN fill in automatically.

🖼️

Text + images

Type + Enter sends text, p pushes your laptop clipboard. On the phone: type, pick from gallery, or shoot.

🔒

LAN-only & PIN-locked

Single WebSocket on your local network, gated by a stable 6-digit PIN. Auto-reconnects forever.

Get running in 2 minutes

  1. Install & start the server with the command above, then run sender-server. A TUI shows your ws://<ip>:8787 address, PIN, and QR code.
  2. Open the phone app — install Expo Go, run npx expo start in mobile/, open Sender, tap 📷 Scan laptop QR.
  3. Done. Type + Enter on the laptop, or Send on the phone. Long-press any phone bubble to copy it back.

Laptop keys

EnterSend typed text to the phone
pPush laptop clipboard (image or text) to the phone
rToggle the pairing QR panel

FAQ

Do both devices need to be on the same Wi-Fi?

Yes. The phone connects directly to ws://<laptop-ip>:8787 over your local network, so both must be on the same Wi-Fi/LAN. Nothing goes through the cloud.

Where is my PIN stored?

Generated once and kept in ~/.config/sender/config.json on the laptop, so you only pair the phone a single time.

Is there a headless mode?

Yes — and it's the default after installing: the installer sets up a background service (systemd on Linux, launchd on macOS) running sender-server --headless, started now and on every login/boot. Logs: journalctl --user -u sender -f. Run the TUI manually with sender-server after systemctl --user stop sender.

How do images travel?

As base64 JSON frames over the WebSocket, capped at 25 MB per image.
